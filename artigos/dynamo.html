Dynamo: Amazon's Highly Available Key-value Store

Paper · Giuseppe DeCandia et al. (Amazon) · 2007

#System Design#Sistemas Distribuídos

Para o carrinho de compras nunca recusar uma escrita, a Amazon trocou consistência forte por disponibilidade e juntou várias técnicas clássicas em um só sistema.

Resumo

O Dynamo é um armazenamento chave-valor interno da Amazon, projetado para um requisito de negócio bem claro: o cliente precisa conseguir adicionar itens ao carrinho mesmo com discos falhando, redes particionadas ou um data center inteiro fora do ar. Para isso, o sistema aceita consistência eventual e deixa conflitos para serem resolvidos na leitura.

O que torna o artigo tão didático é a forma como ele combina técnicas conhecidas, cada uma resolvendo um problema: hashing consistente com nós virtuais para particionar; replicação em N nós com quóruns configuráveis (R + W > N); vector clocks para detectar versões concorrentes; sloppy quorum e hinted handoff para falhas temporárias; Merkle trees para sincronizar réplicas; e um protocolo de gossip para saber quem está no cluster.

Os autores também mostram números de produção, com foco no percentil 99,9 de latência, e não na média.

Por que importa

  • Inspirou diretamente Cassandra, Riak e Voldemort, a família de bancos “estilo Dynamo”.
  • É um estudo de caso completo de trade-offs do teorema CAP em um sistema real.
  • Mostra como escolher técnicas a partir de requisitos de negócio, que é a essência de system design.
