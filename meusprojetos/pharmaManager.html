Demonstração do sistema.

Visão geral

O PharmaManager foi desenvolvido em equipe numa disciplina de Engenharia de Software, com branches por funcionalidade, pull requests e padrão de código verificado por Spotless e Checkstyle (Google Java Style). O back-end é uma API REST em Spring Boot sobre MySQL, e as telas usam HTML, CSS e JavaScript, uma por módulo.

Módulos

Funcionários

Cadastro com cargo e endereço; gerentes e farmacêuticos (com CRF) herdam de funcionário.

Clientes

CPF, contato e endereço, com validações de dados.

Produtos e estoque

Cada unidade é um item com data de vencimento, ligado à entrada de estoque.

Vendas

Associam cliente, farmacêutico e itens, e podem ser desfeitas devolvendo os itens ao estoque.

Fornecedores

Relação muitos-para-muitos com itens por meio de tabela associativa.

Despesas e relatórios

Relatórios de receita × despesa, vendas e estoque gerados em PDF.

Arquitetura

O código é organizado por domínio: cada módulo tem sua própria pasta com Entity, Repository, Service e Controller. Isso deixa as regras de negócio na camada de serviço e os controllers finos. 

src/main/java/com/farmacia/pharma_manager/backend/
├── funcionario/   Funcionario · Repository · Service · Controller
├── gerente/       Gerente (herda de Funcionario)
├── farmaceutico/  Farmaceutico (herda de Funcionario)
├── cliente/   fornecedor/   endereco/   cargo/
├── produto/   estoque/   item/
├── venda/         VendaService · RelatorioVendasService
├── despesa/
└── relatorio/     RelatorioController → PDF (iText)

Banco de dados

O banco pharmabd tem 13 tabelas: cargo, endereco, funcionario, gerente, farmaceutico, cliente, venda, produto, estoque, item, fornecedor, fornecedor_item e despesa. Gerente e farmacêutico usam herança JOINED no JPA: os dados comuns ficam em funcionario e cada subtipo guarda só os seus campos.

Destaques técnicos

Venda transacional, saindo primeiro o que vence primeiro

Uma venda pode ter vários produtos. Antes de gravar qualquer coisa, o serviço soma as quantidades por produto e confere se há estoque para todos. Depois, reserva os itens disponíveis ordenados pela data de vencimento, para que os mais próximos de vencer saiam primeiro. Tudo roda numa transação: se algo falhar, nada é gravado. 

// ItemRepository: itens livres do produto, do vencimento mais próximo ao mais distante

Busca de farmacêuticos

Uma única consulta JPQL procura por nome ou CRF, sem diferenciar maiúsculas e minúsculas.

@Query("SELECT f FROM Farmaceutico f WHERE " +
       "LOWER(f.nome) LIKE LOWER(CONCAT('%', :termo, '%')) OR " +
       "LOWER(f.crf) LIKE LOWER(CONCAT('%', :termo, '%'))")

Relatórios em PDF

O endpoint GET /relatorio?dataInicio=…&dataFim=… monta com iText um PDF de receitas (vendas) e despesas no período e o devolve para ser aberto direto no navegador.
