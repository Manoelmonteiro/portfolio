A ideia

Numa lista de presença, cada assinatura é um traço escuro e predominantemente horizontal sobre papel claro. Se a imagem for limpa e as bordas realçadas, dá para tratar cada assinatura como uma “linha” e contá-las com a transformada de Hough, sem treinar nenhum modelo. Todo o fluxo está num Jupyter Notebook, com uma visualização a cada etapa.

Pipeline

  1. LeituraImagem carregada em escala de cinza.
  2. BinarizaçãoLimiar fixo: pixels < 140 viram preto, o resto vira branco.
  3. RecorteRemove a coluna de nomes à esquerda.
  4. EstiramentoLargura dobrada para alongar os traços.
  5. SobelRealça as bordas dos traços.
  6. HistogramaConta pixels pretos e brancos para calibrar o limiar.
  7. HoughDetecta e conta as linhas horizontais.

Etapa por etapa

1. Leitura e binarização

A foto é lida em escala de cinza e convertida em preto e branco com um limiar fixo. Isso separa a tinta (escura) do papel (claro) e elimina variações de tom. 

src = cv.imread('listaPres.jpg', cv.IMREAD_GRAYSCALE)
dst = src.copy()
dst[dst < 140] = 0      # tinta → preto
dst[dst > 0]   = 255    # papel → branco

2. Recorte e estiramento horizontal

O lado esquerdo da folha (nomes impressos) é cortado em três passos de 150 px, para sobrar só a área das assinaturas. Depois a imagem é esticada 2× na horizontal: cada pixel é copiado para uma coluna par de uma imagem com o dobro da largura. Isso alonga os traços e reforça seu caráter horizontal para as etapas seguintes. 

altura, largura = dst.shape[:2]
imagem_dilatada = np.zeros((altura, largura * 2), dtype=np.uint8)
for y in range(altura):
    for x in range(largura):
        imagem_dilatada[y, x * 2] = dst[y, x]

3. Bordas com Sobel

O filtro Sobel (scikit-image) calcula o gradiente de intensidade e destaca os contornos dos traços e das pautas. O resultado é convertido para 8 bits para ser usado pelo OpenCV.

4. Histograma e limiar adaptativo

O histograma da imagem de bordas é usado para contar pixels pretos e brancos (na imagem de teste, 6.813.352 pretos e 32.896 brancos). A função razao_limiar() transforma essa razão no limiar de votos da transformada de Hough. Ela foi criada porque folhas com pauta geravam linhas demais com um limiar fixo.

5. Transformada de Hough e contagem

cv.HoughLines encontra as retas da imagem. Só são contadas as que têm ângulo próximo de 90° (±10°), ou seja, linhas horizontais como as assinaturas. Se a contagem passar de 100, sinal de que as pautas foram detectadas, o Hough roda de novo com um limiar mais rígido. 

linhas = cv.HoughLines(edges, 1, np.pi / 100, razao_limiar(pretos, brancos, 1))
for linha in linhas:
    rho, theta = linha[0]
    deg = np.degrees(theta)
    if abs(deg - 90) < 10 or abs(deg - 270) < 10:   # linha horizontal
        contador += 1

if contador > 100:   # pautas detectadas: refaz com limiar mais alto
    linhas = cv.HoughLines(edges, 1, np.pi / 100, razao_limiar(pretos, brancos, 0))

Limitações e próximos passos

  • O limiar de binarização e o recorte são fixos e foram ajustados para este tipo de folha. Fotos com outra iluminação ou layout precisariam de recalibração; Otsu ou limiarização adaptativa resolveriam boa parte disso.
  • Uma assinatura longa pode gerar mais de uma linha no Hough. Agrupar linhas próximas pelo rho deixaria a contagem mais robusta.
  • O estiramento com laços em Python é lento em imagens grandes; cv.resize ou fatiamento do NumPy fariam o mesmo em uma linha.
  • O repositório já começou a separar o notebook em módulos (binariza.py), o primeiro passo para virar uma ferramenta reutilizável.
